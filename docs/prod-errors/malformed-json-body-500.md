# SyntaxError: malformed JSON body returns 500 and logs at error level

- **Signature:** `SyntaxError: Unhandled error caught Expected property name or '}' in JSON at position <n> (line <n> column <n>)`
- **First seen:** 2026-10-31 (log timestamp 2026-10-28T18:41:15Z)
- **Occurrences:** 1
- **Routes affected:** `POST /api/v2/auth/login`
- **Investigated:** Read the raw log line: `SyntaxError` thrown from `body-parser/lib/types/json.js:93` via `raw-body`, all third-party frames, no first-party frame. Grepped `src/` for `express.json`, `entity.parse.failed`, `SyntaxError`, `Unhandled error caught`: only `src/middlewares/index.ts:51` (`app.use(express.json())`, no custom error handling around it) and `src/middlewares/errorHandler.ts:41` (`logger.error('Unhandled error caught', ...)`). Read `errorHandler.ts` in full. Checked decisions/index.md, corrections/index.md and existing prod-error records: nothing covers body-parse errors (the related `error-handler-log-level` fix only moved `CustomError` to warn). Single occurrence, no request id in the line, nothing neighbouring to correlate.
- **Root cause:** A client sent a request body that is not valid JSON (failed at position 1, i.e. a body starting with something other than `{`/`"`, e.g. single-quoted or garbage input). `express.json()` (`src/middlewares/index.ts:51`) raises a body-parser error (a `SyntaxError` carrying `status: 400`, `type: 'entity.parse.failed'`) and passes it to `errorHandler`. It is not a `CustomError`, so it falls through to `logger.error('Unhandled error caught')` (`errorHandler.ts:41`) and the response is hard-coded to 500 (`errorHandler.ts:64`) instead of the 400 body-parser intended. The 500 and the error-level log are the defect; the bad input itself is client-side (probe/scanner or a buggy client).
- **Options:** (1) In `errorHandler`, treat `err.type === 'entity.parse.failed'` (or any body-parser error with a 4xx `status`) as a client error: log at `warn`, answer 400 with a generic message. Smallest change, fixes both the wrong status and the monitoring noise (recommended). (2) Wrap `express.json()` with its own error middleware converting to a `CustomError` (400): same effect, more code. (3) Leave alone, one hit in 3 days: keeps wrong 500 semantics and will re-alert on every probe. Also worth a check whether the client sends malformed login bodies (only if it recurs from real users).
